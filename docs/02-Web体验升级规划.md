# 对奏 Duet · Web 体验升级规划

版本：规划稿 1.0 · 2026-09-17  
基线：v0.5.7 / `f04d9d0` / Project schema v8  
方向：**A 的试听舞台 + B 的数据排版**  
状态：R0 已在 v0.5.8 完成，见 [R0 验收记录](03-R0验收记录.md)；R1 视觉样板与基础组件已在 v0.6.0 实施，见 [R1 视觉规范与验收](04-R1视觉规范与验收.md)。R2—R5 继续按下列规划推进。

本规划替代《01-施工总案》中与本轮产品方向、视觉规范、多方／多样本范围和桌面版有关的旧决策。旧文档的历史记录、现行实现说明和仍适用的开发规范继续保留。用户本轮指令优先于旧文档中的“仅双方”“多页非目标”等限制。

## 1. 产品目标与范围

让评测者把素材和判断组织成一场**好看、可控制、可追溯的对比演示**。优先服务音乐生成评测，同时让图片、视频、文字和参数比较共用基础能力。

核心体验：录入素材 → 整理测试题与作品 → 填写观察与结论 → 编排演示 → 直接演示／录屏／导出。

优先级依次为：展示质量与内容可读性、操作与数据可靠性、编辑效率、功能数量。现有 Vue／TypeScript／Pinia／IndexedDB 与命令／撤销机制继续使用。

| 范围 | 决定 |
| --- | --- |
| 本轮实施的第一交付目标 | 双方音乐／图片场景、全应用设计系统、统一编辑器、已确认缺陷修复、可靠导出 |
| 下一步能力 | 同工具多作品、多个测试题、PPT 式按键演示及基本样式预设 |
| 后续扩展 | 3—6 方对比、全体／重点／单项观看方式、用户保存版式预设 |
| 现在建立的扩展基础 | 稳定的参评对象、测试题、样本、场景与运行状态边界；不让新代码继续依赖固定 A/B 数量 |
| 终止 | Tauri／Rust 桌面版开发、原生安装包、桌面专属桥接与相关承诺 |
| 保留 | Web、本地优先、PWA、离线缓存、工程文件、长图与网页导出 |
| 暂缓 | 账号／云同步／协作、平台内容抓取、自动评分、任意 CSS 编辑器、自由坐标画布、自动视频渲染、完整 DAW 时间线 |

“未来可能实现”按扩展路线管理，不把全部未来能力强行塞进第一版；每个阶段必须带来完整可用的体验。

## 2. 统一产品概念

| 概念 | 用户含义 | 例子与边界 |
| --- | --- | --- |
| 项目 | 一次完整评测 | 中文音乐生成工具评测 |
| 参评对象 | 一个要被比较的工具配置 | Suno 某版本；同工具另一版本可另建对象，不能以 toolId 代替参评对象 ID |
| 测试题 | 共同输入与评价条件 | 城市雨夜／旷野清晨；不同题的结果不会自动当作同题横比 |
| 样本／作品 | 某对象在某题下的一份完整产出 | 一首音乐及封面、歌词、生成参数、评分、片段标记和简评 |
| 内容区段 | 一个评测维度或共享内容区 | 提示词、作品试听、人声表达、成本、结论；承载现有模块 |
| 场景 | 演示中的一页画面 | 封面、命题、试听、参数比较、结论 |
| 步骤 | 场景内一次显露或焦点变化 | 显示观察点、突出样本 B、揭示工具身份；多数场景可只有一步 |
| 版式／风格 | 布局结构／统一视觉外观 | 成对舞台／墨色；比较表／纸白 |

测试题和场景不是同一层：一道题可以讲三页；同一份作品可以在试听、评分和结论中引用，不复制内容。

同一首作品的多张封面图属于作品内图集；多首独立产出属于多个样本。图片生成中，一张独立产出可为一个样本；一组需要一起评价的图也可作为一个样本的图集。

## 3. 全应用信息架构

### 3.1 外壳

- 顶部保留项目名称、明确的保存状态、撤销／重做、预演／演示及导出入口；减少多层横条，不让侧栏、标签栏、工具条重复展示项目名称。
- 项目管理保留多项目与搜索；编辑时允许折叠。不要同时常驻项目树、场景树和样本树三条左侧栏：同一左区用明确分组／切换承载。
- 新建页以精致的成稿缩略图展示“音乐评测、图片评测、通用比较”，让用户先理解最终效果。
- 工具库负责工具资料与默认图标；项目内的模型版本、备注和身份显示属于参评对象配置，避免修改一个项目影响其他项目。
- 设置按“工作区外观、编辑行为、素材与存储、语言、关于”组织；项目风格留在项目内。
- 空状态、加载、失败、无数据和成功反馈共用组件与语气；简短成功反馈不覆盖录屏画面。

### 3.2 编辑器

桌面默认布局为**结构区—实时预览—属性区**。建议起始宽度：左 220—260px，右 300—340px，中间自适应。1280px 下先收起项目导航或属性区，优先给作品预览留足空间。

- 左：章节／区段、参评对象与样本，按当前任务切换，支持排序与显隐。
- 中：所选场景的真实渲染结果。选择模块只增加细轮廓与少量操作；未选中的内容保持成稿外观。
- 右：模块为“内容／样式／联动”；选中场景时为“内容／样式／演示”。不同对象不强行显示无意义标签页，但位置和组件保持一致。
- 删除、更换文件、布局预设应用等操作可撤销；短字段支持 Enter 提交，长文本遵循已有自动保存语义。
- 提供明确的“恢复项目默认”与“重置本项”，避免用户不知道当前值来自哪里。

复杂歌词、长文本、图集和参数表使用同一套扩展编辑器：固定标题栏、主体独立滚动、必要时带预览、固定底部状态。普通编辑继续自动保存，底部用“完成”；破坏性确认与导出窗口保留自身语义，不套成自动保存表单。

桌面窗口建议分 S/M/L 三档宽度，统一圆角、内边距、关闭按钮和遮罩；窄屏可占满可用区域。所有模态框必须包含初始焦点、Tab 循环、Esc、关闭后焦点恢复和背景隔离。长标签允许换行，说明不直接塞进开关名称。

## 4. 展示视图的视觉系统（最高优先级）

### 4.1 基调

默认“墨色舞台”：近中性的深色背景、清楚的文字、低饱和身份色、媒体主画面、细线数据比较。B 的贡献是排版逻辑，不是必须把数据场景切成白底。

补充“纸白阅读”作为整份作品的可选外观。项目内部默认使用同一主题；工作区主题与项目主题分别保存。录屏时更改系统深浅色不应改变当前项目的演示外观。

初始设计候选值，正式 token 需在实际组件上校验后冻结：

| 角色 | 墨色候选 | 纸白候选 | 使用方式 |
| --- | --- | --- | --- |
| 舞台底色 | `#101314` | `#F2F0E9` | 大面积中性背景 |
| 表面 | `#181C1D` | `#FBF9F3` | 需要区分区域时使用 |
| 主文字 | `#ECE8DF` | `#222C2C` | 标题、正文、关键值 |
| 次文字 | `#A6AAA5` | `#626C66` | 说明、标签；实测对比度 |
| 对象 A/B | 暖砂金／雾青 | 对应加深版本 | 小标记、波形、进度、当前对象 |
| 额外对象 | 低饱和蓝灰／玫灰／橄榄灰／紫灰 | 对应加深版本 | 与 A—F 标签同时使用 |

颜色职责分为工作区操作色、对象身份色、状态色。成功／警告只表达状态；不以红绿或颜色本身定义胜负。共享提示词使用中性面，默认不再自动混出第三种强调色。旧项目的自定义色保留在兼容外观中。

### 4.2 删除重复装饰，建立层级

- 常规数据与文字不再统一套“染色背景＋左边亮线＋圆角卡片”。
- 对象名与模型版本是精简身份栏，不再占一整张高卡片；实际媒体占据主要面积。
- 参数使用行、表头、数值对齐、必要分隔线；单位与数值分层，不把每个值放进独立小框。
- 歌词附属于当前试听区，默认显示当前句和少量上下文；完整歌词在详细模式查看。
- 短评有明确正文与依据，不用过多胶囊标签包装。
- 背景图案默认关闭，保留细微可选纹理；关闭持续扫描光带、持续呼吸阴影等默认装饰。
- 同一屏只设置一个首要焦点，次要内容通过字号、位置和空间退让。

### 4.3 字体、网格与素材

以 1920×1080 演示稿为主要设计标尺：安全边距建议 64px，区域间隔 32px；场景标题 40—52px、对象名 28—36px、重点评分 36—48px、主要正文／歌词 22—28px、辅助文字 16—18px。字体随统一版式缩放，不能逐模块随意缩小到不可读。

字体以可离线、覆盖中文的可靠字体栈为基础，拉丁字与数字统一度量；品牌标题可使用单一展示字体，正文不混用多种字体。数据开启等宽数字。正式字体授权和打包方式在视觉样板阶段确认，不让网络字体成为演示必需条件。

- 双方媒体采用相同可视区域和一致的 fit 策略，作品比例不同不能无提示裁切关键内容。
- 图片默认完整展示，可切换裁切填充并设置焦点；评分视图内缩略图不代替原图。
- 无封面时提供精致、中性的占位版式，按需使用工具标记；不显示巨大的默认汉字图标。
- 标题超过两行时提示作者缩短或换版式；完整名称在详情保留，不能静默丢字。
- 圆角使用少量层级：控件 6px、表面 10px、弹窗 14px；媒体可按风格使用小圆角或直角。不滥用大圆角和玻璃效果。

## 5. 场景版式与画面比例

首批提供五种语义版式：封面／命题、成对作品、媒体＋观察、维度比较表、结论。它们使用同一标题区、身份规则、数据组件和页边距。

### 5.1 剧场模式与阅读模式

**剧场模式**用于演示与录屏，默认 16:9，一页一个场景。按可用视口等比适配；外侧留白使用项目底色。内容超出时在编辑器提示“需要拆页／精简”，提供拆场景或切阅读版；不能在演示时自动把文字缩得更小或偷偷裁掉。

**阅读模式**用于完整报告，按章节自然向下排列；支持长歌词、长参数表、响应式重排。它与剧场模式引用同一内容和设计组件，但允许不同流式布局。

1080p 演示为主验收，另验收 1440×900、1366×768 与 1280×720；4K 适配使用同一逻辑坐标。手机以阅读模式和单项／重点对比为主；不承诺在手机横向塞下六个完整媒体面板。

### 5.2 多方布局规则

| 人数 | 总览默认布局 | 深入查看 | 数据呈现 |
| --- | --- | --- | --- |
| 2 | 等宽成对舞台 | 单项放大／恢复成对 | 两列比较表 |
| 3 | 宽屏 3 列，紧凑屏改重点对比＋索引 | 任选两项，保留全体位置 | 三列比较表 |
| 4 | 2×2 | 固定参照对象＋当前对象 | 四列或分组表 |
| 5—6 | 3×2，五项时最后一行居中且单元尺寸一致 | 全体总览／重点双人／单项 | 可读时全体表，否则分页并重复维度名与固定参照 |

“同时对比六个”必须在桌面总览中同时看到六个对象；音乐总览显示身份、作品、试听入口和少量状态，详细歌词与长评留给重点视图。图片总览保证缩略图足够大；同级对象使用同尺寸，不因正在播放而自动改变列宽。

固定参照对象是可选操作。切换重点对比保留对象顺序、样本选择和返回位置；身份标签绑定稳定 ID，不随排序重新编号。首期支持 2—6；更多对象待实际布局与性能验证后开放。

## 6. 按键驱动的演示流程

默认故事：**命题 → 作品 → 差异 → 结论**。模板自动生成起点，作者可增删、复制、排序和隐藏场景。故事结构只引用内容，不生成另一份易失同步的评测数据。

场景可有多个显露步骤，例如先出现媒体，再出现短评，最后揭示身份。作者可“添加一步”，首期限制为显示内容、聚焦对象、切换预设样本、揭示身份四类操作；没有任意时间轴编辑器。

| 按键 | 剧场模式含义 |
| --- | --- |
| → / PageDown / Space | 下一步；当前场景步骤完成后进入下一场景 |
| ← / PageUp | 上一步；回退到前一个确定的场景状态 |
| Home / End | 开始／最后场景，默认暂停播放 |
| P | 播放／暂停当前选定媒体 |
| 1—6 | 选择对应对象并转移视觉焦点；不会单凭数字键自动出声 |
| Enter | 放大选定对象／进入重点比较；界面提供等价按钮 |
| F | 全屏／退出全屏，保留普通窗口可演示能力 |
| Esc | 先关闭弹层／退出局部放大；其次退出全屏；再退出演示，各层一次只处理一级 |
| ? | 查看快捷键，暂停场景推进 |

翻页器按常见 PageUp／PageDown 支持；同一按键只绑定一个主要含义。焦点在输入、选择器、按钮或媒体原生控件时优先保留控件语义；ignore composing／键盘连发；弹窗由最上层处理事件。Web 播放依赖实际成功事件：`play()` 被浏览器拒绝时保留“待播放”，显示一个可操作入口，不伪装正在播放。[播放 API 说明](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play)

演示顶部控制在普通窗口可见；全屏录制时提供极简控制层，进入热区、键盘聚焦或点击屏幕边缘才显示。提供一键“干净画面”：去除编辑入口、调试信息、版本号与常驻快捷键提示。退出入口仍能通过键盘和边缘控制找到。

### 6.1 状态必须可复现

运行态至少有 sceneId、stepIndex、caseId、selectedSampleByParticipant、focusIds、revealedIdentities、transportState。切场景不写入项目内容、不污染撤销栈。

进入场景从该场景保存的默认选择与步骤计算画面；回退重建确定状态，不能依赖一串未撤销的 DOM 动画。当前场景内的临时样本选择可返回恢复；“从头演示”清空临时选择。保存为场景默认需要显式操作。

下一步默认不触发播放；作者开启“此步骤试听”后才在明确用户操作下尝试播放。场景切换默认暂停离场媒体；同一媒体连续场景仅在作者明确选择“延续播放”时保留。切换测试题或作品一定终止旧媒体的输出。

## 7. 多作品与测试题切换

### 7.1 用户操作

- 在参评对象下添加样本，可批量导入文件；每份样本包含名称、素材、封面、歌词、参数、评语、评分及片段标记。
- 在作品标题旁使用紧凑选择器；音乐较多时支持搜索列表，图片支持缩略图条。只有一份样本时不出现多余选择控件。
- 切换测试题时，全体对象进入该题下保存的默认样本。缺少产出的对象显示“本题未提供样本”，不能沿用上一题的作品假装有结果。
- 对象内独立换作品时，其他对象不变，所有可见对象始终显示明确样本名。
- 需要整组切换时使用“对比组合”：显式保存 participantId → sampleId 映射。不能把各对象列表的第 N 个天然当成同一轮。
- 同题的共享条件集中展示；样本特有的参数覆盖单独记录并可查看。

### 7.2 切换行为

切换时暂停旧媒体，解除旧轨道订阅，取消未完成的旧加载；进入加载态，待新素材确认就绪后再展示。迟到的旧请求不能覆盖新选择。

默认从 0 开始并保持暂停。只有同一音轨定位或显式“对齐试听”才保留公共时间／片段映射。音乐长度不同不做隐式百分比映射；某侧没有对应片段时明确提示，不擅自寻找替代位置。

歌词、进度、封面、评分和短评通过同一个样本引用解析。替换音频但保留旧歌词时，在编辑器标出需要核对的关联；用户确认是否沿用。资产使用引用而非复制 blob。

删除被场景引用的样本时，提供替换引用或移除引用的选择；可撤销。隐藏与删除保持不同语义。展示缺项有意保留对应位置，编辑空占位则不进入成稿。

## 8. 媒体与对比公平性

- 默认独听：一次只有一个选定对象发声。试听 A/B 必须是切换音源，而不是把多条音乐混在一起。当前双轨同步可保留为高级比较模式，不作为六方默认行为。
- 媒体组件的播放按钮独立于封面和波形开关；至少有一个可见、可用的播放入口。
- “同一时间”与“同一段落”分别配置。简单起点偏移先做，详细段落映射后续再加；不承诺自动对齐。
- 默认音量设置一致并保留可见调节；不把统一音量百分比宣称为响度一致。响度测量／归一化先作为后续专项；启用前不能自动处理音色、音量或评分。
- 真实频谱只反映当前播放数据；没有数据时使用静态占位波形，不把装饰动画宣称为真实分析。
- 六方总览可见六个对象，但只激活当前试听轨道；仅预热当前与可能切换的参照对象，其他使用缩略图／元信息。Web Audio 资源按需创建并管理生命周期。[Web Audio 实践说明](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)
- 暂停、切项目、关预览、删除样本后，不得留下后台声音或重复 rAF／AudioContext／事件监听。
- 图像、视频和 3D 使用显式焦点查看。六个视频不默认同时解码播放，六个 3D 不默认同时自动旋转。

## 9. 数据比较与结论表达

参数表与评分使用共享维度定义：名称、类型、单位、评分范围、优劣方向、可选解释；每个样本只提供对应值与依据。

- 0 分有效；未评分为 null，显示“—”。不能因空输入把缺项变成 0。
- 数字右对齐或按小数点对齐；长文字左对齐；同维度保持同尺度。
- 满分不同、单位不同或测试条件不同的值，不能直接排名。必要换算必须显示规则。
- 默认不自动生成“冠军”、平均分或总分；作者可以给出结论。后续若加汇总，必须明确权重、缺项处理和样本范围。
- 评语可以附“样本／时间点／图像位置”引用；点击引用返回对应内容，再返回时恢复表格位置。
- 多方表头固定对象顺序，默认不在讲解中突然按分数重排。
- 导出显示当前样本选择和测试题；全样本统计是独立能力，不把当前可见样本的分数当成工具整体表现。

## 10. 用户外观与布局定义

第一阶段提供有限但有用的控制；高级功能建立在同一规则内。

| 层级 | 首批开放 | 后续开放 |
| --- | --- | --- |
| 项目风格 | 墨色／纸白、对象配色预设、细微纹理开关、Logo／署名显隐 | 保存个人风格预设、自定义背景素材及其对比度保护 |
| 场景布局 | 五种版式、正文／媒体比例的少量预设、标题与说明位置、内容显隐 | 六方布局、固定参照、用户保存自己的版式组合 |
| 模块外观 | 对齐、字号档位、图片 fit／焦点、封面／波形／歌词显隐 | 受约束的局部细调 |
| 演示行为 | 步骤、身份揭示、聚焦方式、动效关闭／标准 | 组合切换、更多预设过渡 |

样式按“系统默认 → 项目预设 → 场景覆盖 → 少量模块覆盖”解析；每级可恢复继承。预设保存结构与外观，不偷偷包含真实作品、品牌文件或评价。布局修改支持撤销及即时预览。

首期不开放任意 CSS、绝对坐标、自由图层和任意字体混排。这样既可定制，又能维持多方对齐、响应式和导出效果。旧手工背景／字号保留在旧项目兼容层，用户切新风格前看到转换预览。

## 11. 动效规范

动效用于建立顺序、表示状态与连接相同对象。优先 transform／opacity；避免大面积滤镜、闪烁和长时间装饰。

| 动作 | 目标时长 | 表现 |
| --- | --- | --- |
| 控件反馈／状态变化 | 120—180ms | 颜色、细轮廓或轻透明度变化 |
| 样本切换 | 180—260ms | 保持容器尺寸，内容淡换；加载与失败有明确状态 |
| 场景切换 | 280—420ms | 小位移＋淡入；成对对象同步出现 |
| 全体到重点对比 | 240—320ms | 位置关系明确；不让标题、数据和媒体分别乱飞 |
| 评分与证据显露 | 180—240ms | 分组出现；不播放从 0 滚到目标分数的夸张数字动画 |
| 歌词推进 | 120—180ms | 当前句清晰变化，长歌词采用稳定锚点 |

这些是设计目标，不是当前性能测量。动画快速中断时以最后请求为准；翻页不排队播放积压动画。减弱动态效果模式保留完整信息，取消位移／缩放并使用短淡入或立即切换；系统偏好通过 `prefers-reduced-motion` 解析。[媒体查询说明](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)

## 13. 数据与渲染架构

### 13.1 当前需要解除的约束

- `Sheet.sides` 在类型层仍为 `[Side, Side]`；校验只要求至少两项，类型／校验／渲染数量约束不一致。
- `CompareCanvas` 与 `CanvasRow` 有前两侧、A/B 宽度、通用内容属于第一侧等假设。
- `useAudioClock` 按 sideId 保存单个媒体元素，样本与同侧多媒体切换会产生覆盖风险。
- 资源遍历／导出／维护存在各自路径，新增样本后可能漏导出、误清理未激活资源。
- HTML 导出复制当前 DOM、删除作用域属性并写死主题，无法作为未来有步骤和样本切换的主要输出架构。

### 13.2 建议的数据形态

外层 Project 的 ID、标题、时间、标签等继续保留。新比较内容结构建议如下，正式类型名可按代码规范调整，归属关系应维持一致：

```text
Project
├─ participants: Participant[]                   // 稳定 ID，可有相同 toolRef
├─ cases: ComparisonCase[]
│  ├─ sharedInput / testConditions
│  ├─ sections: Section[]                        // 顺序、维度、shared/comparison
│  │  └─ sharedModules[]                         // 仅共享区拥有
│  └─ entries: Record<ParticipantId, Entry>
│     ├─ defaultSampleId
│     └─ samples: Sample[]
│        ├─ id, title, runMetadata
│        ├─ contentBySection: Record<SectionId, ModuleInstance[]>
│        ├─ sectionState                       // 隐藏／兼容布局等
│        └─ evidence / metricValues
├─ presentation
│  └─ scenes: Scene[]                            // 引用 case/section/participant/sample
├─ appearance                                    // 项目风格、有限覆盖
└─ editorPreferences                             // 折叠、选中等非内容偏好
```

Scene 保存引用、版式、所选对象、默认样本选择、步骤及少量样式覆盖。当前播放时间、是否播放、临时聚焦和临时揭示放在独立运行态，不序列化为项目正文。

现有 ModuleInstance 与各模块 data schema 尽量复用。评分维度定义归测试题／区段，样本保存值；旧 score 模块通过适配映射，不能为统一表格而丢失旧值。

资产 blob 继续放独立 assets store。工程内容只持有引用。全项目资源收集采用单一遍历器，覆盖所有样本、未显示区段、场景背景、对象图标和派生封面，并供导出、备份、删除与孤立资产清理共用。

首期界面仍开放两方时，新接口必须面向集合；第三至第六方由后续阶段开放。校验按文件 schema 能力判断，不让旧版本静默截断新工程。参评 ID／样本 ID／场景 ID 与嵌套引用做唯一性和完整性校验。

### 13.3 渲染与交互边界

```text
Project content ──> SceneResolver ──> ResolvedScene ──> SceneRenderer
                          ↑                                  ├─ 编辑预览
                 PresentationSession                        ├─ 剧场演示
                                                             ├─ 阅读报告
                                                             └─ PNG / 网页输出
```

SceneResolver 统一处理样本选择、内容可见性、身份显示、缺项和风格继承；组件不各自读取一套“当前 A/B”。布局使用同一组件集合，阅读与剧场采用明确的不同排版策略。

PlaybackSession 以 projectId + participantId + sampleId + moduleId 标识轨道；歌词显式绑定 trackId。兼容旧 sideId 时先解析当前唯一默认媒体，不让覆盖成为隐式行为。媒体在稳定宿主内挂载，布局切换与编辑／预演切换不创建重复播放源。

内容修改走现有命令层；将来增加 participant、case、sample、scene、appearance 命令。运行态动作独立，不进入内容撤销。复制项目必须重新生成并映射所有实体 ID，包括场景与证据中的引用。

## 14. 旧工程迁移与回退

迁移从 schema v8 开始，实施时按顺序升版本；不要把本规划当作已完成的 schema v9。历史 v1—v8 迁移保留。

1. 对旧项目建立可恢复副本，验证其引用完整性和资产情况；迁移失败保留原记录，不写半份新结构。
2. 原 sides 映射为 participants，保留 ID 和名称、版本、图标、匿名及字号配置。
3. 建立“默认测试题”，每个对象建立“默认作品”；原 paired 行映射 comparison sections，其 modules 连同 title、props、hidden、locked 全部保留。
4. 原 full 行内容移到共享区，保留原顺序。若非首侧也有隐藏内容，不丢弃：进入明确的兼容记录和恢复入口，先校验再转换，不能只取第一侧后删除余项。
5. 保留旧布局快照与兼容长页，先确保旧成稿仍可打开。转换成新剧场场景使用“另存升级副本”，作者预览后决定，不直接覆盖旧外观。
6. 新项目从新模板开始；旧项目可按明确规则生成命题／作品／数据／结论场景。无法可靠分类的模块留在“补充内容”，不凭类型自动删除或认定无用。
7. `.duet` 导入、数据库升级、复制、导出再导入使用同一迁移函数；资源哈希去重继续有效。
8. 新版本识别旧文件；旧版本遇到新文件应明确拒绝。保留迁移前副本是回退途径，不承诺新结构能无损降级到旧客户端。

PWA 更新有未保存内容或正在演示时不强制刷新。数据库版本被旧标签页阻塞时提供可恢复的提示；新旧版本不可同时用不同结构写同一项目。

## 15. 导出与展示一致性

| 输出 | 范围与行为 |
| --- | --- |
| `.duet` 工程 | 全参评对象、测试题、全部样本、场景与外观；明确素材是否完整，不能只导出激活样本 |
| 当前场景 PNG | 确定的 scene/step/sample 选择、主题与身份状态；默认导出场景完整内容，允许选择当前步骤 |
| 阅读长图 | 选定测试题与样本组合的完整报告；长图超限时分页输出并明确页序 |
| 只读网页 | 阅读模式为基础，具备可用的媒体播放；场景与样本切换成熟后增加同一运行态的剧场模式 |
| 视频文件 | 本轮不制作视频渲染流水线；提供稳定、干净、按键可控的录屏画面 |

短期先修复当前导出：保留匹配 CSS 的作用域属性、携带实际主题、将隐藏 audio 转为有 controls 的原生播放、清理不该出现的编辑交互、统一匿名元信息。

中期由同一渲染内核生成只读数据与最小运行时，避免复制一棵正处在播放／动画中间的 DOM。导出快照只使用一个确定的 ResolveContext；截图前等待字体、媒体解码和布局稳定，按输出需要固定当前媒体帧。

可携带网页所需脚本、样式与媒体必须按导出范围内嵌／打包；超过可承受体积时改成明确的阅读快照或媒体包，不能承诺超大单 HTML 永远可行。普通本地网页播放失败时可回退原生控件；高级操作的支持情况在导出界面说明。

身份遮罩用于现场揭示，与“真正不包含身份的匿名分享”分开：

- 现场揭示稿可包含真实身份，默认遮住，后续按作者步骤揭示。
- 匿名分享包不包含身份映射，不提供恢复真实身份按钮；同步清理顶栏、文件名、alt/title、元信息和嵌入数据。提示作者检查图片／音频内容本身是否暴露身份，不承诺自动识别所有媒体中的品牌。
- `.duet` 是可编辑源文件，默认含完整数据；不把它宣传为匿名分享包。

## 18. 验收标准与测试矩阵

### 18.1 每次视觉交付的门槛

1. 展示视图没有编辑边框、删除按钮、调试文案、空白占位或没有标题却占空间的行头。
2. 重要文本不依赖 hover 阅读；中文长标题、无封面、横竖图、混合长度歌词有可读版式。
3. 同级对象等权排布、相同媒体 fit 规则；可见比较值对应当前显示样本。
4. 音乐播放／暂停／切样本／换场景不让画布尺寸跳变。离场内容不会继续发声。
5. 录屏尺寸下主要信息无需浏览器放大；密集内容提供拆页或阅读模式，不能无限缩字。
6. 对比度检查覆盖实际混色、控件状态和媒体背景上的文字，不只验证 token 表。
7. 弱化未播放对象时仍能读名字、关键数据与操作；focus-visible、键盘路径和减少动效模式完整。
8. 深色与纸白使用同一组件和排版逻辑，不出现某个弹窗还是旧紫色皮肤。

### 18.2 必测内容

| 维度 | 样例 |
| --- | --- |
| 人数 | 2／3／4／5／6；相同工具不同版本；很长的工具名 |
| 样本 | 各 1／2／10；某方无样本；数量不等；被场景引用后替换／删除 |
| 媒体 | 短／长音频、无封面、不同长度、损坏文件、外链不可用、横／竖图片、图集、长歌词 |
| 数据 | 0／未评分、小数、不同满分、不同单位、长文本、缺少证据 |
| 演示 | 前进回退、跳页、快速连按、输入焦点、全屏层级、临时揭示、暂停后换样本 |
| 输出 | 两种外观、阅读／剧场、PNG／HTML／duet 往返、非激活样本资产、身份元信息 |
| 迁移 | 历史 schema 样本、隐藏模块、多媒体、旧自定义背景、未知／高级模块、损坏引用 |
| 浏览器 | 当前稳定 Chromium、Firefox、Safari 的 Web 主流程；手机阅读模式；最终记录实际测试版本 |

### 18.3 性能目标

以下为设计验收目标，R1／R2 需记录测试设备后测量，不当作当前已达到的数字：

- 主要控件反馈在约 100ms 内可见；本地已就绪样本的视觉切换约 300ms 内完成，解码等待另有加载态。
- 场景过渡以 60fps 为目标；记录 30 次切换的帧时间，不以录屏“看着流畅”代替测量。目标 p95 帧间隔不高于约 20ms，低性能设备优先简化动画。
- 稳态切换不出现连续阻塞输入的长任务；大文件解析／缩略图／波形生成移到可取消任务，必要时使用 worker。
- 六方×每方十样本的压力夹具不一次解码全部资源；切换五十次后媒体元素、对象 URL 与监听数量不持续增长。
- 沿用现有首屏 gzip 预算作为约束，新增沉重查看器按需加载；功能阶段在增加依赖前给出体积影响。

## 19. 风险与应对

| 风险 | 对应处理 |
| --- | --- |
| 先扩功能导致视觉再次碎裂 | 五类场景、常用控件、窗口样板先冻结；每个新模块必须用样板验收 |
| 六方看不清 | 桌面总览限摘要，重点比较看细节；数据表按可读宽度分页；手机切阅读 |
| 多样本导致串音／错歌词 | 复合 trackId、原子选择、取消旧加载、稳定媒体宿主 |
| 旧工程损失 | 备份、显式迁移、兼容画布、升级副本、全量引用遍历 |
| 自定义越多越难看 | 约束式版式／风格继承，少量可逆覆盖；不开放自由 CSS |
| 网页导出与应用不同 | 共用解析与渲染、确定输出状态、实际打开并操作导出文件 |
| 未保存内容被更新覆盖 | PWA 更新延期、保存状态明确、版本升级／阻塞处理 |
| 过度承诺浏览器性能 | 记录实际设备／浏览器版本与媒体夹具；超限有显式降级路径 |

## 20. 本轮交付与实施起点

本规划覆盖完整 Web 外壳、编辑器、展示系统、媒体、导出、数据迁移及后续扩展。第一实施目标为 **R0—R2：可靠且精致的双人 Web 体验**，不先交付一个充满未来开关的空壳。

本轮另有[可交互展示蓝图](design/web-upgrade-blueprint.html)，演示已选择的视觉方向及 2／6 方、重点比较、作品切换、键盘换章和统一编辑器。它是规划原型，没有真实媒体播放，也没有持久化与完整步骤引擎，不能作为功能已实现的证明。其数值、曲名和评语均为虚构示例。可下载 HTML 后在浏览器中打开，文件不依赖外部资源。

后续施工应先解决 R0 已复现缺陷，再以 R1 样板校准展示质量。R2 才把样板全面接入现有项目；R3—R5 在稳定基础上逐步开放，避免再次靠局部补丁积累风格分歧。
