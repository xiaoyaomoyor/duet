## 1. 命名决策记录（ADR-0001）

### 1.1 候选评估

命名采用 **中文名（对外传播）+ 英文标识（仓库/域名/npm/CLI）** 双轨制。

| 候选 | 英文标识 | 评估 |
| --- | --- | --- |
| **对奏** | `duet` | 「对」= 对立、对质、对着弹；「奏」= 演奏。**同时含"对唱"与"对擂"**，一个"对"字把"和"与"比"说尽。两字、上口、Logo 可做成两段波形面对面 |
| 二重奏 | `duet` | 音感最好，但只有"和"没有"比"，描述协作而非对抗，**已否决** |
| 较场 | `joust` | 谐音「校场」= 比武校阅之地，「较」直接=比较、较量。评测竞技场气质最强 |
| 双镜 | `twinlens` | 两台镜头对准同一事物，同框即对比。视觉系统好做 |
| 并奏 | `duet` | 两声部同时进行、当场比对，比"二重奏"多一层横向张力 |
| 比物 | `paragon` | 出自"比物丑类"，古典路线，字面直接就是"比" |
| 格物 | `gewu` | "格物致知"，文化厚度最高，但与"对比"的关联需一句副标题解释 |
| 万物对比 | `versus` | 最直白的品类名，但无商标性与辨识度，SEO 也弱 |
| 对台 | `faceoff` | 唱对台戏，最好懂但偏随意；`FaceOff` 已被 LLM benchmark 占用 |

### 1.2 最终结论（已定稿）

> **中文「对奏」，英文标识 `duet`，本地目录 `Duet`，仓库名 `duet`，协议 AGPL-3.0。**

品牌描述句（对外统一使用）：

> **对奏 Duet — 让两个工具，同台演奏同一道题。**
> *Same prompt. Two tools. One stage.*

选它的核心原因：「对」同时含"对唱"与"对擂"——**一个"对"字把"和"与"比"说尽**。
这是"二重奏"做不到的：二重奏只有"和"，描述的是协作而非对抗。

### 1.3 全局替换约定（保留）

名称已定稿，但下列约定继续有效，用于降低未来任何改名成本：

1. 代码中**禁止硬编码产品名**。所有展示名从 `src/app.config.ts` 读取：
   ```ts
   // src/app.config.ts
   export const APP = {
     nameZh: '对奏',
     nameEn: 'Duet',
     slug: 'duet',
     fileExt: 'duet',          // 工程文件扩展名 .duet
     dbName: 'duet-db',
     repo: 'https://github.com/xiaoyaomoyor/duet',
   } as const
   ```
2. 工程文件扩展名为 **`.duet`**；若未来改名，只需改 `fileExt` 与 `.duet` 相关的 3 处常量 + 文档全局替换。
3. `[to-be-replaced]` 标记已全部清除——文档中不再存在任何占位名。

## 2. 产品定位

### 2.1 一句话定位

> 一个**专注内容横向对比**的本地优先 Web 应用：把两个工具在**同一套输入**下的产出，按模块并置成一张可编辑、可展示、可导出的对比页。

### 2.2 形态对标

- **应用形态**对标开源项目「魔方简介」：单页应用、离线可用、双击即用、无账号体系、数据全在本地。
- **内容结构**对标 LLM 评测平台（LMArena / Artificial Analysis）：左右并置、分维度打分、可对外展示。
- **信息组织**对标 Obsidian：左侧项目列表 + 顶部标签页 + 工程文件可携带、可迁移。

### 2.3 与竞品/替代方案的差异

| 替代方案 | 它的做法 | 我们的差异 |
| --- | --- | --- |
| Excel / Notion 表格 | 纯文字罗列，媒体只能贴链接 | 媒体原生内嵌、可播放、有动效 |
| 剪辑软件（PR/剪映） | 能做对比视频，但过程重、不可复用 | 一次配置、随时切换编辑/展示、可直接导出长图与只读页 |
| LMArena 等在线评测站 | 只支持 LLM 文本，数据在别人服务器 | 支持音乐/视频/3D/音频/图片/代码任意内容，数据 100% 本地 |
| 手工截图拼图 | 灵活但极难维护、无法二次编辑 | 工程化：改一处，展示视图与导出同步更新 |

### 2.4 目标用户

| 用户 | 场景 | 核心诉求 |
| --- | --- | --- |
| AI 工具评测博主 / UP 主 | 制作「可灵 vs 即梦」对比视频 | 展示视图要好看、动效足、能直接录屏或导出长图 |
| 模型/工具选型者 | 团队内选型汇报 | 结论一目了然、可导出只读页分享给同事 |
| 提示词工程师 | 同一 prompt 跨模型跑结果 | 快速录入、批量建项目、模板复用 |
| 兴趣爱好者 | 对比两台相机、两款游戏、两个商品价格 | 零门槛、不用登录、双击就能用 |

### 2.5 非目标（明确不做，防止范围蔓延）

- ❌ 不做账号体系、不做云端同步、不做多人实时协作（v1）。
- ❌ 不做在线抓取/爬取第三方平台内容（用户自己提供素材）。
- ❌ 不做 AI 自动评分/自动生成结论（人来做判断，工具只负责呈现）。
- ❌ 不做移动端编辑（展示视图需在手机上可读，但编辑假定桌面 ≥1024px）。
- ❌ 不做服务端渲染与 SEO 站点（纯 SPA + 本地优先）。

## 3. 核心用户旅程

### 3.1 主旅程：做一次音乐对比

```
① 打开应用 → 底座为「项目列表 + 标签页 + 空状态引导」
② 点「新建对比」→ 选模板「音乐对比」
   → 自动生成：左侧 Suno、右侧 Lyria，含[封面][歌词][音频 Player][进度条]四行
③ 编辑视图逐行填写：
   - 点封面格 → 上传本地图片 → 自动生成缩略图
   - 点歌词格 → 导入 .txt / 直接粘贴 → 支持 LRC 时间轴
   - 点音频格 → 拖入 mp3 → 自动解析时长、生成波形
   - 双方主题色：左紫 / 右青（默认）
④ 点「展示视图」→ 只读、动效全开
   - 点「同步播放」→ 两首歌从同一时刻起播，进度条联动
   - 按 Esc 退出展示视图
⑤ 点「导出」→ 长图 PNG / 只读 HTML / .duet 工程文件
⑥ 自动保存已生效（防抖 300ms 落盘 IndexedDB）
```

### 3.2 关键体验红线（不可妥协）

| # | 红线 | 说明 |
| --- | --- | --- |
| R1 | **零配置可用** | 首次打开到能开始编辑 ≤ 2 次点击 |
| R2 | **永不丢数据** | 任何编辑在 500ms 内落盘；关闭标签页前强制 flush；崩溃后可恢复 |
| R3 | **展示视图绝对只读** | 展示态下不存在任何可输入元素，误触不改数据 |
| R4 | **空模块自然消失** | 未填内容的模块在展示视图默认不渲染，不留空白 |
| R5 | **左右可像素级对齐** | 同一行的左右两格顶部对齐、行高由内容撑开，不允许错位 |
| R6 | **媒体不阻塞 UI** | 导入 200MB 视频时界面不卡、有进度反馈 |

## 5. 技术选型（ADR 汇总）

| # | 选择 | 理由 | 备选与否决原因 |
| --- | --- | --- | --- |
| T1 | **Vue 3.5+（`<script setup>`）+ TypeScript(strict)** | 编辑视图是典型的"表单 + 列表增删 + 拖拽 + 响应式联动"，Vue 的细粒度响应式能显著减少手写 diff；生态组件（播放器、拖拽、虚拟列表）成熟 | 原生 DOM：富交互下样板代码过多；React：本项目无服务端渲染与复杂状态共享需求，收益不抵心智成本 |
| T2 | **Vite 6** | 冷启动快、HMR 稳、插件生态齐（PWA / Tauri / 单文件） | —— |
| T3 | **Pinia** | 官方状态方案；setup 语法 store；配合 `storeToRefs` 精准订阅 | 自研 store：省 2KB 但要重造 devtools 与热更新支持 |
| T4 | **Vue Router 4（hash 模式）** | 两个主界面 + 深链（`#/p/:projectId`）；hash 模式保证 `file://` 与 Tauri 下无需服务端改写 | history 模式：静态托管需 fallback 配置，`file://` 直接不可用 |
| T5 | **IndexedDB（手写 Promise 封装，零依赖）** | 唯一能存 Blob 大文件的浏览器存储；手写封装保持可控、可测、无供应链风险 | Dexie：功能强但增加依赖与学习面；localStorage：容量 5MB，存不了媒体，直接淘汰 |
| T6 | **`.duet` 工程文件（JSON，媒体可选内嵌）** | 可读、可 diff、可手工修复；导出即备份 | zip 包：需引入压缩库且不便 diff；纯 JSON 内嵌 base64：大项目膨胀 33% |
| T7 | **`vue-draggable-plus`** | 基于 SortableJS，Vue 3 原生维护（`vuedraggable` 已停止对 Vue 3 的有效维护） | 自研拖拽：触摸/键盘无障碍成本高 |
| T8 | **`html-to-image`** | 长图导出效果优于 html2canvas（保留滤镜、CSS 变量、SVG） | html2canvas：对新 CSS 支持滞后，圆角阴影易失真；需按 §8.6 做健壮性加固 |
| T9 | **Web Audio API（`AudioContext` 单一时钟）** | 双轨同步播放必须共用一个时钟源，`<audio>` 各自为政必然漂移 | 纯 `currentTime` 对齐：漂移可达数百毫秒，音乐对比场景不可接受 |
| T10 | **`vue-i18n`** | 中英双语，v1 至少覆盖界面文案 | 自研 i18n：省不了多少体积，丢失复数/插值等能力 |
| T11 | **CSS 变量 + `data-theme`** | 主题系统零运行时成本，便于导出只读页内联 | CSS-in-JS：运行时开销与导出复杂度都更高 |
| T12 | **Vitest + @vue/test-utils + Playwright** | 单测与组件测试复用 Vite 配置；E2E 覆盖"编辑→展示→导出"主链路 | —— |
| T13 | **vite-plugin-pwa** | 离线可用与安装能力，符合同类开源项目形态 | 手写 SW：生命周期与更新策略易出错 |
| T14 | **Tauri 2** | 复用同一套 Web 代码产出 exe/msi；安装包体积远小于 Electron；原生文件读写绕开 `file://` 与 CORS 限制 | Electron：体积 100MB+；仅 PWA：无法获得真正的本地文件系统能力 |
| T15 | **npm**（非 pnpm） | 与工作区既有项目（`TienChenInvoice`）保持一致，降低协作与 CI 心智成本 | pnpm：更快但引入第二套包管理器约定 |

## 6. 数据模型（唯一真源）

### 6.1 类型定义

```ts
// src/types/project.ts

/** 语义化版本，便于未来迁移 */
export const SCHEMA_VERSION = 1

export interface Project {
  id: string                  // uuid v4
  schemaVersion: number       // 写入时的 SCHEMA_VERSION
  title: string               // 默认「未命名对比」
  createdAt: number           // epoch ms
  updatedAt: number
  tags: string[]              // v1 仅存储与筛选，不做标签管理 UI
  pinned: boolean
  sheet: Sheet                // v1 一个项目 = 一张对比页（v2 改为 sheets: Sheet[]）
  ui: ProjectUiState          // 视图态（展示模式、各侧配色覆盖等）
}

export interface ProjectUiState {
  mode: 'edit' | 'present'
  toolbarCollapsed: boolean
  sidebarCollapsed: boolean
  zoom: number                // 0.5 ~ 1.5，展示视图缩放
}

export interface Sheet {
  id: string
  /** v1 固定 2 侧；v2 允许 >2，渲染层按 sides.length 自适应列数 */
  sides: [Side, Side]
  rows: Row[]
  layout: LayoutConfig
}

export interface LayoutConfig {
  /** 两侧等宽 or 自定义比例；gutter 为中轴间距 */
  ratio: [number, number]
  gutter: number              // px
  density: 'compact' | 'normal' | 'comfy'   // 决定行距与内边距
  showAxis: boolean           // 是否显示中轴光带
  background: 'solid' | 'grid' | 'dots'
  maxWidth: number            // 内容最大宽度 px，默认 1440
}

export interface Side {
  id: string
  toolRef: ToolRef
  accent: string              // 主题色 hex，如 #A78BFA；默认左紫右青
  labelOverride?: string      // 覆盖工具名（例如「可灵 · 1.6 大师版」）
  modelVersion?: string       // 模型子名称/版本号，如 "v3.5" / "chirp-v4"
  note?: string               // 一句话备注，展示在工具名下方
}

export type ToolRef =
  | { kind: 'builtin'; toolId: string }
  | { kind: 'custom'; toolId: string }
  | { kind: 'inline'; name: string; iconAssetId?: string }  // 临时工具，不入库

export interface Row {
  id: string
  /** paired = 左右各一格；full = 单格跨两列 */
  kind: 'paired' | 'full'
```

### 6.2 存储布局（IndexedDB）

数据库名：`duet-db`，版本：`1`。

| Object Store | keyPath | 索引 | 用途 |
| --- | --- | --- | --- |
| `projects` | `id` | `updatedAt`, `pinned` | 对比项目（**不含任何 Blob**） |
| `assets` | `id` | `kind`, `createdAt` | 媒体二进制与派生数据 |
| `tools` | `id` | `kind`, `category`, `name` | 自定义工具（内置工具在代码里，不落库） |
| `settings` | `key` | —— | 单条记录 `key: 'app'` |
| `templates` | `id` | `category` | 用户自建模板（内置模板在代码里） |
| `meta` | `key` | —— | 迁移标记、最后备份时间、配额快照 |

**关键约束**：
1. `projects` 内**只允许存 assetId 字符串引用**，禁止内联 dataURL 或 Blob。违反即为架构性错误（会导致项目读写从毫秒级劣化到秒级）。
2. 所有结构变更必须走 `db/schema.ts` 的 `migrate(db, oldVersion, newVersion)`，**禁止**在业务代码里写"如果没有这个字段就补一个"的兼容分支。
3. 资产引用采用**引用计数惰性回收**：删除项目时不立即删资产；在设置页提供「清理未引用媒体」，扫描所有项目与工具后统一回收。

## 7. 模块系统（本项目的心脏）

### 7.1 设计目标

用户所说的"添加文字模块后把标题改成'价格'、'简评'"——这不是特例，而是**核心机制**：**模块 = 类型（决定怎么渲染和编辑）+ 自定义标题（决定它在这张对比页里代表什么维度）**。因此：

- 同类型模块允许重复添加任意多次。
- 标题完全自由，不做任何枚举限制。
- 每个模块类型自带"呈现能力"（如封面图能换比例、音频能显示波形），但不自带"语义"。

### 7.2 架构：注册表 + 三个契约

**禁止出现巨型 `v-if/v-else` 分支**。所有模块类型通过注册表接入，新增一种模块 = 新增一个目录 + 一行注册，不改动任何既有代码。

```ts
// src/modules/registry.ts
export interface ModuleDefinition<TData = unknown, TProps = unknown> {
  type: ModuleTypeId
  /** 显示名与图标，供模块选择器与默认标题使用 */
  meta: { nameKey: string; icon: string; descriptionKey?: string; category: ModuleCategory }
  /** 数据校验与默认值 */
  schema: { create(): TData; validate(data: unknown): data is TData }
  /** 编辑器：编辑视图里的填写界面 */
  editor: DefineComponent
  /** 渲染器：展示视图里的只读呈现（含全部动效） */
  renderer: DefineComponent
  /** 内容判定：决定"是否算已填写"，用于空模块自动隐藏 */
  isEmpty(data: TData, props: TProps): boolean
  /** 可选：导出长图前的准备（等待媒体加载、字体就绪） */
  beforeExport?: (el: HTMLElement) => Promise<void>
  /** 可选：默认尺寸与呈现选项的元数据 */
  options?: Array<{ key: string; labelKey: string; type: 'select' | 'number' | 'boolean' | 'color'; values?: unknown[]; default: unknown }>
}

export const moduleRegistry = new Map<ModuleTypeId, ModuleDefinition>()
export function registerModule(def: ModuleDefinition): void

// src/modules/index.ts —— 唯一的注册入口
import './text'; import './cover'; import './lyrics'; /* … */
```

### 7.4 空模块与隐藏规则（精确语义）

三个概念必须分清，`isEmpty` 判定由模块自己实现：

| 状态 | 判定 | 编辑视图 | 展示视图 |
| --- | --- | --- | --- |
| **空模块** | `def.isEmpty(data, props) === true` | 显示为虚线占位框 + 类型名 + "点击填写" | **不渲染**（DOM 中不存在） |
| **有内容 + `hidden: true`** | 用户手动关闭可见性 | 显示，标题旁有"眼睛划掉"图标 | **不渲染** |
| **有内容 + `hidden: false`** | 正常 | 显示 | 渲染 |

补充规则：
- 编辑视图可通过设置 `editorShowEmptyModules: false` 隐藏所有空模块（默认 **true**，因为编辑时看不到空模块会找不到位置）。
- `isEmpty` 的实现要求：文本类 `text.trim() === ''`；媒体类 `!assetId`；列表类 `items.length === 0`；评分类 **`score === null` 才算空，`score === 0` 不算空**（0 分是有效评分，这是最容易写错的地方，必须有测试）。
- **整行都空**时，编辑视图保留该行（否则无法继续填写），展示视图整行跳过。

### 7.5 行与对齐机制

- 对比页结构为 `rows: Row[]`，**一行的左右两格天然对齐**，由 CSS Grid 同一网格行承载，行高由较高者撑开，另一格 `align-self: stretch` 但内容 `align-self: start`。
- 不同高度的模块（如左侧视频、右侧文字）不会造成错位——这就是选择"行模型"而非"两个独立列表"的原因。
- 编辑视图每行左侧有拖拽手柄（`vue-draggable-plus`），支持上下排序；每格底部有"＋ 添加模块"按钮，弹出模块选择器（可按分类与搜索）。
- 支持把模块从一格拖到另一格（跨容器拖拽，`group: { name: 'cell', pull: true, put: true }`）。

### 8.1 分层与依赖方向（单向，禁止反向）

```
            ┌──────────────────────────────────────────┐
            │  ui/  (Vue 组件、视图、样式)              │
            └───────────────┬──────────────────────────┘
                            │ 只能向下调用
            ┌───────────────▼──────────────────────────┐

            └───────────────┬──────────────────────────┘
                            │

        └───────────────────┬──────────────────────────┘
```

**硬性规则**：
1. `ui/` 禁止 `import` `db/`；一切持久化经 `stores/` → `services/`。
2. `lib/` 禁止 import 任何上层目录，禁止访问 `window`（除显式传入的 `document` 参数）。
3. 模块（`modules/*`）只能依赖 `lib/` 与 `types/`，**禁止直接访问 stores**；需要全局能力时通过 props 注入（如 `onSeek(t)`、`getAccent()`）。
4. 禁止跨模块 import 彼此的内部文件（`modules/a/inner.ts` 不可被 `modules/b` 引用）。

### 8.3 状态管理：单一写入口（本项目最关键的架构决策）

**所有对项目数据的修改必须经过 `dispatch`**，禁止在组件里直接 `project.rows.push(...)`。

```ts
// src/stores/commands.ts（示意）
export type Command =
  | { t: 'row/add';      row: Row; at?: number }
  | { t: 'row/remove';   rowId: string }
  | { t: 'row/move';     rowId: string; to: number }
  | { t: 'row/relabel';  rowId: string; label: string }
  | { t: 'module/add';   rowId: string; sideId: string; type: ModuleTypeId; at?: number }
  | { t: 'module/remove';rowId: string; sideId: string; moduleId: string }
  | { t: 'module/move';  from: CellRef; to: CellRef; moduleId: string; toIndex: number }
  | { t: 'module/patch'; ref: ModuleRef; patch: Partial<ModuleInstance> }
  | { t: 'module/data';  ref: ModuleRef; patch: Record<string, unknown> }  // 深合并到 data
  | { t: 'side/patch';   sideId: string; patch: Partial<Side> }
  | { t: 'sheet/patch';  patch: Partial<Pick<Sheet, 'layout'>> }
  | { t: 'project/patch';patch: Partial<Pick<Project, 'title' | 'tags' | 'pinned'>> }

export function dispatch(cmd: Command, opts?: { transient?: boolean; coalesceKey?: string }): void
```

由此**一次性获得四个能力**：

| 能力 | 怎么来的 |
| --- | --- |
| 撤销/重做 | 每个 Command 天然可逆；`HistoryStore` 存反向 patch，栈深 100 |
| 自动保存 | 只有 dispatch 会触发 `updatedAt` 与防抖落盘，不会漏也不会重复 |
| 协同/同步（v2） | Command 即操作日志，未来上行到服务端就是现成的 CRDT 前置 |
| 可测试 | 纯函数式的命令应用 `applyCommand(project, cmd)` 可脱离 DOM 单测 |

**连续输入合并**：`coalesceKey`（如 `module:text:${moduleId}`）在 800ms 内的同类命令合并为一条历史记录，避免"打一行字撤销 40 次"。

### 8.4 媒体解析层（`mediaResolver`）

统一解决"assetId 或外链 URL → 能放进 `<img>/<audio>/<video>` 的 src"：

```ts
type MediaSource =
  | { kind: 'asset'; assetId: string }
  | { kind: 'url'; url: string; mirror?: boolean }

interface ResolvedMedia {
  src: string                 // blob: 或 https:
  status: 'ready' | 'loading' | 'error'
  error?: 'cors' | 'network' | 'unsupported' | 'too-large'
  revoke(): void
}

export function resolveMedia(src: MediaSource, opts?: { kind: 'image' | 'audio' | 'video' }): ResolvedMedia
export function useResolvedMedia(src: MaybeRef<MediaSource>, kind: MediaKind): Ref<ResolvedMedia>
```

实现要点：
1. **blob URL 池**：按 `assetId` 缓存，引用计数为 0 后延迟 10s 再 `revokeObjectURL`（避免快速切换视图时反复创建）。
2. **并发闸门**：同一时刻最多 4 个 blob 读取，防止打开大项目时 IO 拥塞。
3. **失败必可见**：`status === 'error'` 时渲染统一的 `MediaErrorPlaceholder`（带具体原因文案 + "重新加载"按钮），**绝不允许静默空白**。
4. **revoke 时机**：组件 `onUnmounted` 时必须调用 `revoke()`；在展示视图切回编辑视图时统一释放。

### 8.5 外链媒体策略（CORS 与防盗链）

这是同类 Web 应用最容易失败的功能，必须按阶梯降级设计：

```
① 用户粘贴外链
    ↓
② 尝试 <img crossorigin="anonymous"> / fetch(url) 探测可读性（3s 超时）
    ↓
③ 可读 → 按用户设置处理：
     mirror（默认）  → 完整下载为 Blob 存入 assets，之后完全本地化，导出也能内嵌
     link            → 仅保存 URL，展示时直接用（首屏快，但导出长图可能空白）
    ↓
④ 不可读（CORS / 防盗链 / 需 Referer）
     → 弹窗三选一：
       (a) 走本地代理缓存（仅 dev 与 Tauri 提供；见下）
       (b) 保留为外链引用，标注"⚠ 可能无法导出长图"
       (c) 取消，改为手动上传本地文件
```

- **开发环境代理**：Vite 中间件 `/__media_proxy?url=` 直连抓取（仅 dev）。
- **Tauri 桌面版**：暴露 `fetch_remote(url)` 原生命令，**完全绕开浏览器 CORS**——这是桌面版最实在的收益之一，必须在 M5 落地。
- **纯 Web 生产环境**：不提供代理（保持零后端承诺），只做 (b)/(c) 提示。
- 所有外链请求：超时 15s、最大体积受 `maxMirrorSizeMB` 限制、失败重试 1 次、错误分类写进 `ResolvedMedia.error`。
- **安全**：镜像的内容一律按原始字节存储，不做任何解析执行；`iframe` 模块强制 `sandbox="allow-scripts"` 且默认关闭，并在 UI 上明示风险。

### 8.6 导出长图（`html-to-image` 加固）

该库在网络字体、跨域图片、Safari 三种情况下会产出空白图，必须做以下加固：

```ts
async function exportLongImage(el: HTMLElement, opts: { scale: 1 | 2 }): Promise<Blob> {
  await document.fonts.ready                       // ① 字体就绪
  await waitForImages(el)                          // ② 所有 <img> complete && naturalWidth>0
  await waitForMediaElements(el)                   // ③ <audio>/<video> 的 poster 或首帧可用
  await inlineExternalImages(el)                   // ④ 外链图片转 dataURL（blob 已本地化的跳过）
  const bg = getComputedStyle(document.documentElement).getPropertyValue('--bg-base')
  const dataUrl = await toPng(el, {
    pixelRatio: opts.scale,
    backgroundColor: bg.trim(),
    cacheBust: true,
    skipFonts: false,
    filter: (node) => !node.classList?.contains('no-export'),   // 排除工具栏等
  })
  return dataUrlToBlob(dataUrl)
}
```

- 长图模式：临时把滚动容器设为 `height: auto; overflow: visible`，截图后还原（用 `document.body.dataset.exporting = '1'` 切换一份专用 CSS，隐藏工具栏、播放按钮等 `.no-export` 元素）。
- 校验：`pixelRatio` 与总高度相乘不得超过 16384px（浏览器 canvas 上限），超限时自动降 `pixelRatio` 并提示。
- **回归测试**：Playwright 中截图后断言 PNG 的**非透明像素占比 > 5%**，直接堵死"导出纯白图"这类事故。

### 8.7 只读 HTML 导出

生成单个 `.html` 文件：内联全套 CSS（`tokens.css` + 组件样式，构建时通过 `?inline` 导入）、内联一份极小的只读渲染运行时、媒体以 data URI 内嵌（小文件）或写入同名 `.assets/` 目录（大文件，选择"分离媒体"时）。

内容与展示视图**视觉一致但交互极简**：可播放音视频、可滚动歌词，其余全部静态。顶部带一行极小的来源标记（可关闭）。

## 11. 主题系统（紫夜 Violet Dark）

### 11.1 Token 唯一来源

`src/styles/tokens.css` 是**唯一**允许出现颜色字面量的文件。组件中一律 `var(--xxx)`；禁止 `color: #a78bfa` 这类硬编码（ESLint 自定义规则 + Code Review 双保险）。

### 11.2 紫夜主题 Token 表

> **M6 更新**：主题从"只有紫夜"扩为四选一（跟随系统 / 暗 / 亮 / 紫夜）。
> 下表是紫夜主题的基准值；暗、亮两套见 `tokens.css` 中各自的 `[data-theme]` 块。
>
> 三条结构性约定：
> 1. **结构性 token（圆角/间距/字体/动效/层级）只在基础块声明一次**，主题块只覆盖颜色。
> 2. `system` **不是配色而是解析规则**：按 `prefers-color-scheme` 落到 `dark` 或 `light`，
>    写入 `<html data-theme>` 的永远是具体主题——CSS 因此不需要认识"系统"这个概念。

- 每个 `Side` 有 `accent`，渲染时写入该侧容器的内联 CSS 变量：

## 12. 动效系统

### 12.1 原则

1. **动效服务于"对比"，不服务于炫技**：所有动效都必须强化"左右并置"这一信息结构（如两侧同时入场、中轴光带自上而下扫过）。
2. **时长纪律**：入场 ≤ 620ms，交互反馈 ≤ 220ms，悬停 ≤ 140ms。禁止超过 1s 的动效。
3. **可关闭**：`settings.reducedMotion` 与 `@media (prefers-reduced-motion: reduce)` 双重生效，关闭后所有动效降级为瞬时切换（保留状态变化，去掉位移与缩放）。
4. **只播一次**：入场动效由 `IntersectionObserver` 触发，元素进入视口播放一次，滚动回看不再播。

### 12.2 动效清单

| ID | 名称 | 位置 | 触发 | 时长/曲线 | 描述 |
| --- | --- | --- | --- | --- | --- |
| A1 | 双侧同步入场 | 对比画布 | 进入展示视图 | 420ms staggered 60ms / ease-out | 左右模块成对从下方 12px 淡入，同一行的左右同时开始 |
| A2 | 中轴光带 | 两列之间 | 展示视图常驻 | 6s 循环 / linear | 1px 竖向渐变光从上到下缓慢扫描，强化"分隔与对峙" |

### 12.3 性能纪律

- 只允许动画 `transform` / `opacity` / `filter` / `box-shadow`；**禁止**动画 `width/height/top/left`（进度条用 `transform: scaleX()` 实现）。
- 频谱与进度用**单个 `requestAnimationFrame` 循环**集中驱动（`services/audioSyncService` 暴露一个 `useRafTick()`），禁止每个组件各自 `setInterval`。
- 页面不可见时（`document.hidden`）暂停 rAF 与频谱计算。
- 展示视图若模块数 > 60，自动关闭 A2/A5/A6 的高开销项并提示（性能预算见 §15）。

## 13. 音频双轨同步播放（A/B 对比试听）

### 13.1 目标

同一套提示词下两个工具生成的音乐，要能**从同一时刻起播、可同步定位、可 solo 单听**，靠人耳判断差异。

### 13.2 技术方案

- **唯一时钟源**：`AudioContext.currentTime`。两个 `<audio>` 元素经 `createMediaElementSource` 接入同一 `AudioContext` 的两个 `GainNode`。
- **起播**：`play()` 时记录 `t0 = ctx.currentTime`，对两侧分别计算 `offset`（用户设定的偏移量，用于补偿前奏差异），通过 `el.currentTime = offset` 对齐后再 `play()`。
- **漂移校正**：每 250ms 采样一次两侧 `currentTime` 差值 `Δ`；`|Δ| > 120ms` 时对落后方执行 `currentTime = 领先方 - offset` 硬校正；`320ms` 后进入稳定区，避免抖动。
- **主时钟选择**：默认以**时长较长**的一方为主时钟；若用户点了某一侧的"设为主轨"，则以其为准。
- **Solo / Mute**：Solo 时把另一侧 `GainNode.gain` 线性淡到 0（80ms），而非直接暂停——保证时钟不中断、切回来仍同步。
- **音量**：各自独立的对数音量滑块（0~1 → `gain` 曲线），默认 0.8。
- **频谱**：两侧各接一个 `AnalyserNode`（`fftSize: 256`），数据驱动 A6 动效。

### 13.3 与歌词/进度的联动

- 若某侧含 `lyrics` 模块且 `syncWithAudio: true`，则该侧歌词按 `audio.currentTime` 定位当前行并平滑滚动（`scrollIntoView({ block: 'center', behavior: 'smooth' })`）。
- 若歌词无 LRC 时间轴，则按"总行数均分总时长"做**估算对齐**，并在 UI 上标注"估算同步"，避免用户误以为是精确同步。
- `progress` 模块绑定 `assetId` 时自动跟随该侧播放进度；拖动进度条调用 `seek(t)`，两侧同时定位（保持 offset）。

### 13.4 浏览器策略与降级

- 自动播放受限：**必须由用户手势触发首次播放**（工具栏按钮），不得在进入展示视图时自动播放。
- 无 `AudioContext`（极老环境）或 `createMediaElementSource` 失败（跨域媒体未带 CORS 头）时，降级为"两个独立播放器 + 手动对齐"，并在 UI 明确提示原因。**降级路径必须有测试覆盖**。
- 跨域外链音频：`<audio crossorigin="anonymous">` 失败则无法接入分析器与增益控制，此时自动走降级路径（仍可播放，但不能同步/A-B）。

**达标手段**：

### 16.2 E2E 必测主旅程

1. **音乐对比全流程**：新建（音乐模板）→ 改两侧工具与版本 → 上传封面 → 导入 .lrc → 上传 mp3 → 切展示视图 → 同步播放 5s → 断言两侧 `currentTime` 差值 < 150ms → 导出长图 → 断言 PNG 非空白。
2. **持久化与位置恢复**：编辑 5 处 → 刷新页面 → 断言全部内容与视图模式恢复 → 关闭浏览器上下文重开 → 断言数据仍在。
3. **空模块规则**：新增 3 个空模块 → 展示视图断言 DOM 中不存在 → 填入其中 1 个 → 断言只有它出现 → 手动隐藏 1 个有内容的 → 断言不出现但在编辑视图仍可见。
4. **自定义模块反复添加**：同一格添加 3 个 `text` 模块，标题分别改为"价格""简评""结论" → 断言三者独立、互不影响、可单独删除。
5. **导入导出往返**：项目 A 导出 `.duet` → 清空数据库 → 导入 → 断言 `deepEqual(原 project, 新 project)`（含媒体尺寸、时长、波形长度）。

## 19. 开发规范

### 19.1 代码规范

- TypeScript `strict: true` + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`。
- 组件一律 `<script setup lang="ts">`，props 用 `defineProps<Props>()` 泛型写法，禁止运行时 `props: {}` 对象写法。
- 组件文件命名 PascalCase；组合式函数 `useXxx.ts`；纯函数文件 camelCase。
- 单个 `.vue` 文件 ≤ 300 行，超过则拆子组件或抽 composable。
- **禁止 any**（必要时 `unknown` + 类型守卫）。
- `console.log` 禁止进主干（保留 `lib/logger.ts` 的统一日志，生产环境静默）。

### 19.2 Git 规范

- 分支：`main`（可发布）/ `feat/xxx` / `fix/xxx`。
- 提交：Conventional Commits（`feat(modules): 新增 timeline 模块`）。
- 每个里程碑打 tag（`v0.1.0-m1`）。
- PR 必须：测试通过、`vue-tsc` 无错、文档已更新。

**这次排查的教训（写入规范）**：

1. **先建可观测性，再改代码。** 前 5 轮我在没有证据的情况下反复改实现、跑 E2E、看截图，浪费了大量轮次。
   正确做法是：把状态渲染成可读探针（`data-*` 属性）→ 用 E2E 精确读取 → 再动手。
   探针法最终一次定位：`cardAsset=b7ff3c47`（卡片收到了新对象）但 `coverAsset=none`（渲染器没有），
   这条对比直接指向"子组件快照"这个根因。
2. **探针本身也会改变被测对象。** 中途我用模板内联表达式写探针，其中使用了可选链 `?.`，
   导致 Vue 模板编译失败、整个画布不渲染，让我误以为"应用崩溃了"。探针要简单、只读、且写法受控。
3. **不能用 PowerShell 做含非 ASCII 文件的文本往返。** 本项目因此损坏过 13 个文件（编码错乱）。
   含中文的源文件一律用文件工具改写；并保留全量编码扫描作为兜底。

**方法论收获（M5 最重要的一条）**：

> **手写解析器必须配"不变量型"测试，而不是"快照型"测试。**

`lib/markdown.ts`、`lib/sanitize.ts`、`lib/gltf.ts`、`lib/mat4.ts`、`lib/textDiff.ts`
这五个文件一共新增 176 条用例，其中真正抓到 bug 的（缺陷 #2、#3、#4）
都不是"输出是否等于某个字符串"，而是三种**不变量**：

- **还原性**：并排 diff 的两侧投影回去必须逐字等于两份原文（丢行是最难肉眼发现的错）
- **结构性**：`<pre>` 永远不能出现在 `<p>` 内部（HTML 解析器会改写 DOM）
- **代数性**：法线变换后必须仍垂直于变换后的切向（方向错了屏幕上看不出来，只觉得"有点暗"）

快照测试只会把当时的错误一起冻结下来。

**方法论收获（M6 最重要的一条）**：

> **"看起来是同一个 bug"的十几个失败，往往是两三个各自独立的根因叠加的。**

这一轮 E2E 从 30 红修到 0，但过程中我的两次判断都被证据推翻：

1. 先以为是"html-to-image 渲染挂起"，加了超时兜底——**兜底没触发**，说明根本没走到渲染。埋点后才发现导出其实是成功的，问题在下载事件。

教训是：**在拿到"确切的错误文本"之前，不要开始改代码。** 前面几轮我在只有现象（超时、白屏）时就开始推测，浪费了大量轮次；而这次一旦把 `[object Event]` 展开成"出错行附近的 SVG 内容"，根因当场就出来了。

**定义**：不分工具、两边通用的内容（同一套提示词、总体评价、音频控制台）。

理由：这样它才是一块**内容**——可以排位置、改标题、随项目一起导出；自动出现的那一条既不能移动，又让"我明明没加它"变成要解释的问题。

#### 六、本轮发现并修复的真实缺陷

| # | 问题 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | **"有 Ctrl+Z 就够了"其实是个空头承诺** | 全仓库搜不到任何 `ctrlKey` 处理（除 Ctrl+K），按钮是撤销的唯一入口 | 先实现快捷键，再删按钮；E2E 改为按 `Control+z` |
| 2 | 展示视图下同步控制栏永久停在"两侧都需要有音频" | 两个前提到达时间不同：`durationMs > 0` 由 loadedmetadata 决定、`element` 登记由 `AudioRenderer` **延后一个 tick** 决定。进入展示视图时旧画布卸载把 element 置空而 durationMs 还留着，第一轮 poll 看到"两侧就绪"却一个 element 都拿不到 → `no-tracks`；而就绪**集合**此后再没变过，`attach()` 也就再没被调用 | `poll()` 里"未装配成功就继续重试"（`attach()` 自带幂等保护，成功后是空转） |
| 3 | 同一项目同时存在**两套画布** | `CompareView` 在展示态下也渲染主区画布，`PresentOverlay` 里还有一份只读画布。两份 `AudioRenderer` 按同一个 `sideId` 互相覆盖登记，两份 `SyncPlayerBar` 互相 attach/detach 同一个引擎 | 展示态下主区画布整块不渲染（它本来就被遮罩层完全盖住），顺带省掉一半渲染与内存 |
| 4 | 亮色主题下品牌 LOGO 完全不可见 | 见上表第 3 条 | CSS mask |
| 5 | 品牌 LOGO 大面积回退到程序化图标 | Simple Icons **没有收录**中文 AI 产品（可灵/即梦/海绵音乐/天工/Tripo3D/Meshy/IndexTTS/GPT-SoVITS 逐个实测 404），补多少行都变不出来 | 登记同一主体的**母品牌**（可灵→快手、Kimi→月之暗面、海螺→MiniMax）；不用"看起来像"的 slug 硬凑——图标错了比没有更糟 |

**方法论收获**：

> **删掉一个入口之前，先确认替代入口真的存在。**

11.1 是一条读起来完全合理的意见（"有 Ctrl+Z 就够了"），而实际情况是那个"就够了"的快捷键从来没有被实现过。
如果照着字面删按钮，交付的会是一个**没有任何办法撤销**的版本，而且不会报错、不会失败——只是按了没反应。
这类"用户以为存在、代码里没有"的功能，验收时最容易被漏掉，因为双方都以为对方会验证。
