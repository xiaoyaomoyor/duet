# ADR-0001 · 产品命名：对奏 / Duet

- **状态**：已采纳（2026-09-15）
- **决策者**：项目所有人
- **影响面**：全局（品牌、仓库名、包名、工程文件扩展名、数据库名、代码标识）

## 背景

本项目需要一个能同时承载两层含义的名字：

1. **并置对照**——把两个工具在同一套输入下的产出放在一起比较（这是产品的唯一动作）。
2. **同台演出**——两个生成物的产出本身带有"作品"属性（音乐、视频、图像），对比过程不应像做表格，而应像看一场对台戏。

候选名中最受欢迎的是「**二重奏 / Duet**」，但它有一个致命短板：**只有"和"，没有"比"**。
二重奏描述的是两个声部的协作，而本产品里左右两方本质上是**对立**的——用户想知道"谁更好"。

## 决策

**对外名称：对奏（Duet）**

| 维度 | 取值 |
| --- | --- |
| 中文名 | 对奏 |
| 英文名 | Duet |
| 代码标识 / 包名 | `duet` |
| 仓库名 | `duet` |
| 本地目录 | `Gewu` |
| 工程文件扩展名 | `.duet` |
| IndexedDB 名 | `duet-db` |

**品牌描述句**：

> 对奏 Duet — 让两个工具，同台演奏同一道题。
> *Same prompt. Two tools. One stage.*

## 理由

「**对**」字同时覆盖了两种语义：

- 对唱、对弹、对奏 → **协作与合奏**（保留二重奏的音感）
- 对质、对擂、对决 → **较量与比较**（补上二重奏缺失的那一半）

「**奏**」保留了音乐/表演的直觉，让产品在音乐、视频、图像等"作品型"对比场景中显得自然，而不像一个评测表格工具。

**一字之差**：把"二重奏"的「二」换成「对」，就从"协作"变成了"协作 + 对擂"。

## 被否决的候选及原因

| 候选 | 否决原因 |
| --- | --- |
| 二重奏 | 只有"和"没有"比"，描述了协作而非对抗 |
| 较场（joust） | 谐音「校场」，评测竞技场气质很强，是次优选；但"较"字略生硬，且不如"对"字口语化 |
| 双镜 / 双格 | 偏静态视觉隐喻，缺少"演奏/产出"的动感 |
| 比物 / 格物 | 有文化厚度，但需要副标题解释，认知成本高 |
| 万物对比 | 直白但无商标性与辨识度 |
| 对台（faceoff） | 最好懂，但偏随意，做开源项目名偏轻 |

## 后果

- 已在 `src/app.config.ts` 集中定义全部名称常量，禁止在代码中硬编码产品名。
- 若未来改名，只需修改 `app.config.ts` + `package.json` + `docs/` 全局替换，**无散落引用**。
- 工程文件扩展名 `.duet` 已写入施工文档 §6.4，一旦发布 v0.1.0 后**不再变更**（避免存量工程文件失效）。
